Build a completely new application from scratch.

This is a real production-oriented Progressive Web App for a handlebar-mounted phone used while riding a **bike or scooter**.

Do not create a static mockup, fake dashboard, fake map, fake GPS, fake routes, or fake AI detections.

The application will eventually combine:

* real GPS speed
* real Mapbox navigation
* destination search
* real routing
* rear-camera perception
* on-device AI object detection
* object tracking
* road/path/lane perception
* rider safety warnings
* an abstract 2.5D driving visualization
* adaptive performance
* Bike/Scooter modes
* PWA installation

However, **do not implement the computer-vision system in this first task**.

The first milestone is the complete, reliable navigation foundation.

---

# 1. Development philosophy

You are working on a real codebase that will continue to be expanded.

Build it as maintainable software, not as a one-off generated website.

Most importantly:

**Do not pretend something works if it does not actually work.**

If an API, browser feature or external service is unavailable, handle that state explicitly.

Do not substitute fake data for real functionality.

Do not create random simulated telemetry.

Do not hard-code a London/Wokingham/etc. location.

Do not create fake search results.

Do not draw fake routes.

Do not create fake AI detection boxes.

---

Implement the project in stages, and **verify each stage before moving to the next**.

# 8. Real GPS

Use the browser's actual Geolocation API.

Preferred implementation:

```ts
navigator.geolocation.watchPosition(...)
```

Create a clean location service.

Expose state similar to:

```ts
interface LocationState {
  latitude: number | null
  longitude: number | null
  speedKmh: number | null
  heading: number | null
  accuracyMeters: number | null
  timestamp: number | null
  status: 'unavailable' | 'acquiring' | 'active' | 'degraded'
}
```

Handle:

* permission denied
* timeout
* unavailable location
* poor accuracy
* stale position
* location loss

Never fabricate coordinates.

# 9. Real speedometer

The speedometer must use actual GPS data.

Prefer:

```text
coords.speed
```

when valid.

If the browser doesn't provide a reliable speed value, derive speed from consecutive GPS positions and timestamps.

Convert to:

```text
km/h
```

by default.

Support mph as a setting.

Use modest smoothing to remove GPS jitter without introducing obvious lag.

Handle:

* null speed
* stale GPS
* unrealistic GPS jumps
* low accuracy

Do not use hard-coded demo speed values.

Do not simulate movement.

# 31. Future collision warning

```text

```

```text

```

For a vehicle or animal, substitute the appropriate object class.

Do not implement:

```text

```

The future safety system must consider:

* confidence
* persistence
* relative position
* path overlap
* apparent closing motion
* rider speed
* rider trajectory
* mode
* hysteresis
* cooldown
